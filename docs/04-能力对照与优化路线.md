# TeleOps 功能与设计概览 · 同类项目能力对比 · 优化路线

> 版本基线：v0.8.22 ｜ 用途：求职/技术评审材料，用于在「企业级电信运维 Agent」赛道中清晰标定本项目的位置、已做功与差距。

---

## 一、TeleOps 是什么（一句话定位）

一个 **「研发造工具、运维复用沉淀」的双角色运维 Agent 作战室**：把大模型（DeepSeek）编排成可诊断根因、可自我扩展工具的运维助手，并通过告警流大屏持续接收告警 → 自动根因分析；同时具备**多租户隔离、操作审计、安全护栏**等一整套企业级底座。

它不是单用户 demo，而是一个**自带权限/审计/安全模型的单机多用户平台**。

## 二、功能与设计总览

### 2.1 核心闭环（最大差异点）
- **「一加二闭环」**：研发 Agent 负责根据运维反馈**构建/沉淀可复用工具**（如 `disk_full_probe`），运维 Agent 负责调用这些工具做诊断；工具经过注册表统一管理，越用越聪明。
- **持续告警流（AlertStream）**：外部系统经 `POST /adapters/alert/ingest` 把告警推入，按业务域多实例运行，前端大屏实时展示解析条数、运行时长（uptime）、运行状态。

### 2.2 架构（五层 · 每层可替换 + 有兜底）
| 层 | 技术 | 可替换性 |
|---|---|---|
| API 层 | FastAPI + JWT 鉴权 | 换成 Flask/其它不动业务 |
| 编排层 | LangGraph 0.2.76（状态图） | 换成 CrewAI / 自写 ReAct 不动工具层 |
| 模型层 | DeepSeek（配置驱动，可换任意 OpenAI 兼容模型） | 换模型只改 `config.py` |
| 知识/工具层 | 函数工具注册表 + 适配器 `src/adapters/` | 向量库可换 Chroma，图库可换 networkx |
| 数据层 | SQLite（自带，零运维） | 换 Postgres 仅改连接串 |
| 前端 | 原生 JS（无框架，零构建） | 可换 Gradio / 纯 API 客户端 |
| 网关 | Caddy（HTTPS 反代，自签证书） | 换 Nginx 不动后端 |

### 2.3 企业级底座（本项目相对多数求职作品的护城河）
1. **多租户三层隔离（v0.8.9–v0.8.15）**
   - 实例隔离：`_streams: Dict[ws_id, AlertStream]`，每个业务域独立告警流；
   - 权限隔离：`is_writable_by(ws_id, user)` 服务端唯一判定入口，公共域仅 admin 可写、私有域仅 owner 可读写；
   - 可见性隔离：`is_visible_to()` 越权读返回 404（不暴露域是否存在）；匿名用户仅见公共域 `core-net`。
   - 铁律：**读过滤 ≠ 写过滤**，读写必须同步校验。
2. **操作审计日志（v0.8.21）**：`audit_log` 表 + 14 类关键动作埋点（注册/登录/登出、业务域增删改、Agent 增改删、告警流启停、工具构建、Demo 重置）+ `GET /audit`（admin 全量 / 普通本人 / 匿名 401）；**旁路设计**——审计写失败静默吞异常，绝不让业务 500；**越权被拒（403）同样留痕**（result=denied），这是审计的核心价值。
3. **邀请码（v0.8.10）**：`TELEOPS_INVITE_CODE`，空=开放注册，非空=必填且错/空统一 403 防旁路探测。
4. **防火墙白名单（v0.8.11）**：`teleops_ctl.py firewall {on,off,status}`，默认放行 RFC1918 私网段，支持 `TELEOPS_FIREWALL_ALLOWED` 自定义；需管理员权限。
5. **零依赖限流（v0.8.12）**：自研滑动窗口（不走 slowapi），登录 5/写 60/读 120 次每分钟每 IP；`/health /metrics /static` 不计额度，429 + Retry-After。
6. **Caddy HTTPS（v0.8.13）**：`scripts/Caddyfile`（443 + tls internal 自签 + reverse_proxy 127.0.0.1:8000）+ `caddy_runner.py`（PID + 端口检查 + PATH/winget 三路径回退 + **PID 文件自愈**）。
7. **进程管理健壮化（v0.8.22）**：`taskkill /F /T` 杀 uvicorn 子进程树；启动回写真实监听者 PID；以端口监听为唯一健康标准。

### 2.4 测试与质量
- 全量 **134 项 pytest**（临时库 + 离线 Mock，不污染运行数据）。
- 测试隔离铁律：触碰 `data/` 运行时文件必须 `monkeypatch + tmp_path`，严禁删改生产 PID 文件。

## 四、明确可优化项（按优先级）

### P0 — 拉开差距的关键（建议优先）
1. **接入真实电信数据集**
   - 现状：告警流目前吃 BlueGene 公开日志，行业属性弱。
   - 做法：复用 `src/adapters/` 架构，新增 `5G_kpi_adapter`（映射 `uccmisl/5Gdataset` 或 OSS 导出）实现 `parse_webhook`，把真实 5G KPI/告警喂进 `alert_stream`。README 立刻从「作品」升级为「行业方案」。
2. **补量化对比指标**
   - 现状：只有功能演示，无 MTTR / 根因 Top-1 准确率 / 噪声抑制率。
   - 做法：跑 10–20 条真实故障，记录上述指标，文档里放一张表。比纯功能展示有说服力得多。

### P1 — 企业级闭环补全
3. **人工审批（HITL）闭环** ✅ **已实现（v0.8.35）**
   - 两层设计：① 构建期全局闸——`TELEOPS_REQUIRE_APPROVAL` 环境变量 + admin 运行时开关（`POST /settings/require-approval`，落 `data/settings.json` 持久化），开启后 `tool.build` / `stream.start` 高风险动作不再直接执行，落 pending 审批单；② 运行时按工具风险——`ToolRegistry` 的 `require_human_approval` 标志（如 `restart_service`=高危）由运维 Agent 在派发前二次确认。
   - 闭环：`GET /approvals`（admin 全量 / 普通用户仅见自己）→ `POST /approvals/{id}/approve`（admin 批准后真正执行：tool.build 跑研发造工具、stream.start 真正启动流）→ `reject` 拒绝不执行；全部进审计日志。详见 `docs/07-人工审批HITL闭环.md`。
4. **MCP 接真实运维系统**
   - 现状：适配器是「预留占位 + demo 兜底」。
   - 做法：把 `real_adapters.py` 接 Grafana/Prometheus 查询，让 Agent 能拉真实指标做诊断（对齐 TelcoNet）。

### P2 — 锦上添花
5. **SSO / OIDC 登录**：当前 JWT + 邀请码，可补 OIDC 对接企业 IdP（对标 TelcoNet）。
6. **告警抑制率看板**：前端大屏加「噪声抑制数 / 根因命中率」统计卡片。
7. **可回放审计**：审计日志导出 + 时间线回放（对标 AgentOS 的可回放）。

### 已在做的事（别重复造）
- 多租户三层隔离、审计旁路、自研限流、Caddy HTTPS、进程管理健壮化——均已落地且全量测试覆盖，**这是现成护城河，面试直接甩**。
