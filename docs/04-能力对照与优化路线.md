# TeleOps 功能与设计概览 · 同类项目能力对比 · 优化路线

> 版本基线：v0.8.22 ｜ 用途：求职/技术评审材料，用于在「企业级电信运维 Agent」赛道中清晰标定本项目的位置、已做功与差距。

---

## 一、TeleOps 是什么（一句话定位）

一个 **「研发造工具、运维复用沉淀」的双角色运维 Agent 作战室**：把大模型（DeepSeek）编排成可诊断根因、可自我扩展工具的运维助手，并通过告警流大屏持续接收告警 → 自动根因分析；同时具备**多租户隔离、操作审计、安全护栏**等一整套企业级底座。

它不是单用户 demo，而是一个**自带权限/审计/安全模型的单机多用户平台**。

## 二、功能与设计总览

### 2.1 核心闭环（最大差异点）
- **「一加二闭环」**：研发 Agent 负责根据运维反馈**构建/沉淀可复用工具**（如 `disk_full_probe`），运维 Agent 负责调用这些工具做诊断；工具经过注册表统一管理，越用越聪明。
- **持续告警流（AlertStream）**：外部系统经 `POST /adapters/alert/ingest` 把告警推入，按业务域多实例运行，前端大屏实时展示解析条数、运行时长（uptime）、运行状态。

### 2.2 架构（五层 · 每层可替换 + 有兜底）
| 层 | 技术 | 可替换性 |
|---|---|---|
| API 层 | FastAPI + JWT 鉴权 | 换成 Flask/其它不动业务 |
| 编排层 | LangGraph 0.2.76（状态图） | 换成 CrewAI / 自写 ReAct 不动工具层 |
| 模型层 | DeepSeek（配置驱动，可换任意 OpenAI 兼容模型） | 换模型只改 `config.py` |
| 知识/工具层 | 函数工具注册表 + 适配器 `src/adapters/` | 向量库可换 Chroma，图库可换 networkx |
| 数据层 | SQLite（自带，零运维） | 换 Postgres 仅改连接串 |
| 前端 | 原生 JS（无框架，零构建） | 可换 Gradio / 纯 API 客户端 |
| 网关 | Caddy（HTTPS 反代，自签证书） | 换 Nginx 不动后端 |

### 2.3 企业级底座（本项目相对多数求职作品的护城河）
1. **多租户三层隔离（v0.8.9–v0.8.15）**
   - 实例隔离：`_streams: Dict[ws_id, AlertStream]`，每个业务域独立告警流；
   - 权限隔离：`is_writable_by(ws_id, user)` 服务端唯一判定入口，公共域仅 admin 可写、私有域仅 owner 可读写；
   - 可见性隔离：`is_visible_to()` 越权读返回 404（不暴露域是否存在）；匿名用户仅见公共域 `core-net`。
   - 铁律：**读过滤 ≠ 写过滤**，读写必须同步校验。
2. **操作审计日志（v0.8.21）**：`audit_log` 表 + 14 类关键动作埋点（注册/登录/登出、业务域增删改、Agent 增改删、告警流启停、工具构建、Demo 重置）+ `GET /audit`（admin 全量 / 普通本人 / 匿名 401）；**旁路设计**——审计写失败静默吞异常，绝不让业务 500；**越权被拒（403）同样留痕**（result=denied），这是审计的核心价值。
3. **邀请码（v0.8.10）**：`TELEOPS_INVITE_CODE`，空=开放注册，非空=必填且错/空统一 403 防旁路探测。
4. **防火墙白名单（v0.8.11）**：`teleops_ctl.py firewall {on,off,status}`，默认放行 RFC1918 私网段，支持 `TELEOPS_FIREWALL_ALLOWED` 自定义；需管理员权限。
5. **零依赖限流（v0.8.12）**：自研滑动窗口（不走 slowapi），登录 5/写 60/读 120 次每分钟每 IP；`/health /metrics /static` 不计额度，429 + Retry-After。
6. **Caddy HTTPS（v0.8.13）**：`scripts/Caddyfile`（443 + tls internal 自签 + reverse_proxy 127.0.0.1:8000）+ `caddy_runner.py`（PID + 端口检查 + PATH/winget 三路径回退 + **PID 文件自愈**）。
7. **进程管理健壮化（v0.8.22）**：`taskkill /F /T` 杀 uvicorn 子进程树；启动回写真实监听者 PID；以端口监听为唯一健康标准。

### 2.4 测试与质量
- 全量 **134 项 pytest**（临时库 + 离线 Mock，不污染运行数据）。
- 测试隔离铁律：触碰 `data/` 运行时文件必须 `monkeypatch + tmp_path`，严禁删改生产 PID 文件。

## 四、明确可优化项（按优先级）

### P0 — 拉开差距的关键（建议优先）
1. **接入真实电信数据集** ✅ **已实现（v0.8.37，管线打通）**
   - 现状：告警流此前吃 BlueGene 公开日志，行业属性弱；现已接 `uccmisl/5Gdataset` 真实 5G KPI。
   - 做法：复用 `src/adapters/` 架构——`FiveGKpiAdapter`（id `alert-5g`）新增 `load_dataset_alerts` +
     `src/adapters/fiveg_dataset.py` 加载器（列名容错 + 按指标方向定阈值，解决 RSRP/RSRQ/SNR「越低越差」反算）；
     `scripts/fetch_5g_dataset.py` 取数、`scripts/replay_5g_dataset.py` 回放到 `/adapters/alert/ingest`，
     经 `parse_webhook` → 统一 Alert → 运维 Agent 根因。**README 已由「作品」升级为「行业方案」**。
   - ⚠️ 前提澄清：`uccmisl/5Gdataset` 是**客户端侧被动 KPI 时序，无根因标签**——已验证「真实 KPI→根因」整条管线，
     但**根因 Top-1 准确率 / 噪声抑制率**已由 v0.8.38「量化评估基准」通过**合成注入故障**测得（见 P0-2）；
     真实 OSS 导出（带告警+拓扑）可进一步提升样本真度——**切源能力已就绪（零代码）**：
     `data/adapters.json[alert-5g].column_aliases` 运行时覆盖列名映射（华为/中兴/爱立信差异），
     模板见 `data/adapters.example.json` 的 `_oss_example`；用户给导出文件（CSV）即填映射切源。
     另：真实数据噪声大，默认 `min_severity=major` 抑制 warning 级健康波动。
2. **补量化对比指标** ✅ **已实现（v0.8.38，真·根因 Top-1 + 噪声抑制率）**
   - 现状：此前 `/metrics/summary` 大屏的「根因 Top-1 0.875 / 噪声抑制 1.0」是**假指标**——
     旧 `scripts/eval_closed_loop.py` 用独立关键词匹配器 `diagnose()` **完全绕过 `OpsAgent.rootcause`**，
     噪声抑制也只是机械计数 `is_noise`，与真实管线无关。v0.8.38 新建 `src/eval/rootcause_bench.py`
     **真正接 `OpsAgent` + 真实 triage 降噪层**：合成注入 5G 故障造带 `true_root` 标签小样本，
     算**置信度口径 + 位置口径双 Top-1** 与**真实噪声抑制率**，并诚实标注 `verify_mode`
     （offline-stub / live-agent / simulated 修复仿真，前端会如实显示）。
   - 做法：默认 `python scripts/eval_closed_loop.py`（stub 离线、确定性、零额度）；
     加 `--live` 接真实 DeepSeek 评估（需 `DEEPSEEK_API_KEY`）；`--error-rate` 注入不完美推理验证指标敏感。
     前端 `/metrics/summary` 读 `data/eval_results.json` 现显示真实指标，替换旧假值。
   - 注意：MTTR 仍缺（需带时间戳的工单闭环，待真实 OSS 数据）；先补根因 Top-1 / 噪声抑制两块即已拉开差距。

### P1 — 企业级闭环补全
3. **人工审批（HITL）闭环** ✅ **已实现（v0.8.35）**
   - 两层设计：① 构建期全局闸——`TELEOPS_REQUIRE_APPROVAL` 环境变量 + admin 运行时开关（`POST /settings/require-approval`，落 `data/settings.json` 持久化），开启后 `tool.build` / `stream.start` 高风险动作不再直接执行，落 pending 审批单；② 运行时按工具风险——`ToolRegistry` 的 `require_human_approval` 标志（如 `restart_service`=高危）由运维 Agent 在派发前二次确认。
   - 闭环：`GET /approvals`（admin 全量 / 普通用户仅见自己）→ `POST /approvals/{id}/approve`（admin 批准后真正执行：tool.build 跑研发造工具、stream.start 真正启动流）→ `reject` 拒绝不执行；全部进审计日志。详见 `docs/07-人工审批HITL闭环.md`。
4. **MCP 接真实运维系统** ✅ **已实现（v0.8.40，对齐 TelcoNet）**
   - 落地：`GrafanaAdapter`（Grafana 数据源代理）、`PrometheusAdapter`（直连 Prometheus `/api/v1/query_range`）、`LokiLogAdapter`（LogQL 查 Loki `/loki/api/v1/query_range`）三者齐备，均「配置驱动 + demo 兜底」——`data/adapters.json` 配 `base_url`+`api_key` 即切真实监控，未配返回仿真时序/日志，单测与演示不依赖外部实例。
   - 端点：`POST /adapters/metrics-grafana|metrics-prometheus/query` 拉指标时序；`POST /adapters/logs-loki|log-elk/logs` 拉日志。Agent 诊断阶段可主动查真实监控（对齐 TelcoNet 的 Grafana/Prometheus/Loki/Tempo 能力）。
   - 接入真实监控：见 `docs/09-接入真实监控系统.md`。

### P1.5 — 容量调优（演进中）
5. **异步审计写** ✅ **已实现（v0.8.36）**
   - `src/core/audit_queue.py`：`AuditWriter` 单例（有界队列 + daemon 消费线程 + atexit flush）。`_audit_write` / `_audit_write_dummy` 改为异步入队，请求路径零阻塞；后台线程串行消费 `db.audit`（经 `_LOCK` 线程安全，存储语义不变），队列满降级、atexit 排空不丢审计。测试 `tests/test_audit_queue.py` 4/4 全绿。
6. **待做（垂直扩容，建议在 D3 无状态化打底后推进）**

   - SQLite→Postgres：连接串切换即可（`docs/04:28` 数据层已预留），需补迁移脚本；

   - 长期演进清单见 `EVOLUTION_BACKLOG.md`。
