## 2. 本地开发（Windows 本机）

### 2.1 启动后端

```bash
# 推荐：用进程管理脚本（后台 + PID 文件 + 端口兜底）
python scripts/teleops_ctl.py start
#   默认绑 TELEOPS_HOST=0.0.0.0:8000；PID 写入 data/.server.pid

# 裸启备选（调试用）
python -m uvicorn src.api.server:app --host 127.0.0.1 --port 8000 --reload
```

### 2.2 访问

- 浏览器打开 `http://127.0.0.1:8000` 即主界面（`web/` 8 视图）
- `/docs` 看 Swagger；`GET /health` 看版本与健康；`/audit` 看操作审计

### 2.3 进程管理脚本（常用）

```bash
python scripts/teleops_ctl.py status     # 进程 PID / 实际监听 PID / 健康 / 局域网 URL
python scripts/teleops_ctl.py restart    # 先停（杀进程树）后起
python scripts/teleops_ctl.py stop       # taskkill /F /T 杀树（uvicorn 派生子进程）
python scripts/teleops_ctl.py logs       # 最近 50 行日志
python scripts/teleops_ctl.py toggle     # 运行中则停，停则起
```

> 前端改完需 `Ctrl+Shift+R` 强刷，并确认 `web/index.html` 的 `app.js?v=x.x.x` 缓存戳已更新。

### 2.4 防火墙白名单（局域网安全）

```powershell
# 右键 PowerShell → 以管理员身份运行
python scripts\teleops_ctl.py firewall on     # 放行 RFC1918 私网段，公网默认阻断
python scripts\teleops_ctl.py firewall status
```
详见 `docs/安全加固使用指南.md` 第 1 节。

## 3. Windows 本机 HTTPS（Caddy 反代）

让密码/JWT 走加密通道，避免明文 HTTP 被截获。

```bash
# 首次：下载 caddy.exe 到 tools/（GitHub 限速时改用 winget install CaddyServer.Caddy）
python scripts\caddy_setup.py

# 确保后端已在 8000 运行，再起 HTTPS 反代
python scripts\teleops_ctl.py start
python scripts\teleops_ctl.py caddy on
#   443 反代 127.0.0.1:8000，tls internal 自签证书

python scripts\teleops_ctl.py caddy status   # 查看 PID / 端口
python scripts\teleops_ctl.py caddy off      # 停止（PID 丢失也会按端口兜底杀）
```

- 浏览器打开 `https://127.0.0.1:443`（或 `https://<局域网IP>:443`），忽略自签证书警告。
- **PID 自愈**：PID 文件丢失/过期但 443 仍在监听时，`caddy_status()` 反查真实 PID 并回写，避免误报未运行、停不掉。

## 4. Docker 自托管（上公网）

> 本沙箱无 Docker，以下为交付物，在 Linux 服务器或 Windows + Docker Desktop 执行（详见 `deploy/README.md`）。

### 4.1 目录

```
deploy/
├── docker-compose.yml   # backend + caddy 两服务（+ 可选 prometheus/grafana）
├── Dockerfile           # python:3.11-slim，仅装真实依赖
├── requirements.txt     # 精简依赖（剔除 gradio/chromadb/pandas/httpx/pyyaml）
├── Caddyfile           # 自动 HTTPS 反代 backend:8000
├── .env.example        # 密钥样例
└── README.md
```

### 4.2 快速开始

```bash
cd /path/to/TeleOps
cp deploy/.env.example deploy/.env
nano deploy/.env          # 填 DEEPSEEK_API_KEY / TELEOPS_DOMAIN / TELEOPS_INVITE_CODE ...

docker compose -f deploy/docker-compose.yml up -d --build
docker compose -f deploy/docker-compose.yml logs -f
```

- 业务数据落在 named volume（`teleops_data/kb/tools/traces`），重启不丢。
- 密钥只存在于宿主 `deploy/.env`，`.dockerignore` 已排除，镜像层无明文。
- 可观测性（可选）：`docker compose -f deploy/docker-compose.yml --profile observability up -d` → Grafana `:3000`。

### 4.3 两种用法

| 场景 | 配置 |
|---|---|
| 本地自测 localhost | `TELEOPS_DOMAIN=localhost`，Caddy 内部 CA 自签 |
| 公网生产 | 域名 A 记录指向公网 IP；`TELEOPS_DOMAIN=域名`；`TELEOPS_ACME_EMAIL=真实邮箱`（Let's Encrypt 非交互必需）；安全组放行 80+443 |

### 4.4 公网上线前安全检查清单（必逐项确认）

- [ ] 域名 A 记录指向公网 IP，`ping 域名` 可达
- [ ] 安全组/防火墙放行 **80 与 443**（80 用于 ACME 验证，缺一不可）；**不要**直接把 8000 暴露公网
- [ ] `TELEOPS_ACME_EMAIL` 已填真实邮箱（Caddy 非交互申请证书）
- [ ] `TELEOPS_API_TOKEN` 已设（写接口鉴权开启），前端「设置」填相同值
- [ ] `TELEOPS_INVITE_CODE` 已设（关闭开放注册，防公网随意注册）
- [ ] Grafana 若开启：改强密码并移除匿名访问两行
- [ ] 验证：`curl -I https://域名/health` 返回 200，地址栏显示有效锁标（非自签警告）

## 7. 常见部署故障

| 现象 | 原因 | 解决 |
|---|---|---|
| `firewall on` 报添加失败 | 缺管理员 | PowerShell 右键「以管理员身份运行」 |
| Caddy 启动后访问超时 | 443 被 Windows 默认策略拦 | `firewall on`（含 443 入站） |
| 浏览器提示「不安全」但能进 | 自签证书 | 预期，点「高级→继续」 |
| 重启后端后管理端看不到改动 | 改了 DB 但 registry 是内存态 | `restart` 后端，或改 DB 后重启 |
| 局域网设备无法访问 | 网段不在 RFC1918 白名单 | 设 `TELEOPS_FIREWALL_ALLOWED` |
| `caddy off` 停不掉 | PID 文件丢失/过期 | 已自愈：按 443 端口反查真实 PID 杀 |
