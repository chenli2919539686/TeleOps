# 5G 小区 KPI / 告警数据导出需求清单（给网优 / O&M 团队）

> **用途**：我们做一个「小区级 KPI → 自动根因分析」的运维工具，需要一份**小区级 KPI 历史报表（CSV）**做回放与验证。
> 这份清单告诉你：**导出什么、列名怎么叫、格式有什么要求**。按表导出一份 CSV 发回即可，列名不一致也没关系（我们有列名映射，会自动对齐）。
> 预计耗时：5–10 分钟（性能报表模块直接导出）。

---

## 一、需要导出什么

| 类型 | 是否必需 | 说明 |
|---|---|---|
| **PM 性能报表**（小区级 KPI 时序） | ✅ 必需 | 每行 = 一个小区在某个时间点的指标采样。这是根因分析的主输入。 |
| **FM 告警日志**（同期故障/告警） | 可选（强烈建议） | 含告警类型、级别、时间、小区。能直接作为根因真标签，大幅提升评估可信度。 |

**时间范围建议**：连续 1–7 天、按 15 分钟或 1 小时粒度即可（不必全量）。样本量 1000 行内都好处理。

---

## 二、字段对照表（系统里列名叫什么都行，对照填即可）

下表「系统常见叫法」列里的名字我们**已自动识别**；如果你们的列名不在表里，导出后在备注里写一下，我们一对一映射（零代码改动）。

| 类别 | 规范列名 | 系统常见叫法（已自动识别✅） | 必需 | 方向（值越…越差） | 单位 |
|---|---|---|---|---|---|
| 时间 | `Timestamp` | `Time`✅、`ts`✅、采样时间、StartTime | ✅ | — | 建议 `YYYY-MM-DD HH:MM:SS` |
| 小区标识 | `CellID` | `Cell ID`✅、`eNodeB ID`、`gNodeB`、`CI`、`Cell`✅ | ✅ | — | 文本/编号 |
| 参考信号接收功率 | `RSRP` | `LTE_RSRP`、`RSRP(dBm)` | ✅ | 越低越差 | dBm |
| 参考信号接收质量 | `RSRQ` | `LTE_RSRQ` | 推荐 | 越低越差 | dB |
| 信噪比 | `SNR`（即 SINR） | `SINR`✅、`SNR` | 推荐 | 越低越差 | dB |
| 信道质量指示 | `CQI` | `CQI`、`CQIIndex` | 推荐 | 越低越差 | 无 |
| 接收信号强度 | `RSSI` | `RSSI` | 可选 | 越低越差 | dBm |
| 下行吞吐 | `DL_bitrate` | `DL_Throughput`✅、`Downlink`✅、`DL THR` | 推荐 | 越低越差 | Mbps |
| 上行吞吐 | `UL_bitrate` | `UL_Throughput`✅、`Uplink`✅、`UL THR` | 推荐 | 越低越差 | Mbps |
| 丢包率 | `PINGLOSS` | `Packet_Loss`✅、`PingLoss`✅、`丢包率` | 推荐 | 越高越差 | % |

**可选辅助列**（进 tags，辅助根因定位，不影响解析）：
- 站号 / 基站 ID（`eNodeB`/`gNodeB` 与小区标识不同时）
- 频点 / 频段（`Earfcn`/`Arfcn`/`Band`）
- 邻区关系、经纬度（`Longitude`/`Latitude`，地图展示用）
- 制式（`NR`/`LTE`）

**铁律只有两条**：① 有「时间列」+「小区标识列」；② 至少有**一类无线 KPI 或丢包/吞吐**。其余列名随便。

## 三、格式与交付要求

1. **文件格式**：优先 **CSV**（UTF-8 或带 BOM 均可，我们会自动识别）。如果是 Excel（`.xlsx`），请「另存为 CSV」即可；我们暂只认 CSV。
2. **编码**：`UTF-8` 或 `GBK` 都行（中文表头我们会规整）。
3. **一行 = 一个小区一个时刻**的一行一条记录（宽表：指标各占一列）。
4. **时间**：尽量 `YYYY-MM-DD HH:MM:SS`；如果是 Unix 时间戳或 `YYYY/MM/DD` 也行，我们做规整。
5. **不要做聚合**：保留原始粒度（不要先算日均/小区均值），我们要看时序退化特征。
6. **交付方式**：把 CSV 直接发回，或先贴**表头一行 + 2~3 行样例数据**也足够我们写好映射。

## 四、各厂商导出路径速查（给操作人员参考）

- **华为 U2020 / iManager M2000**：`维护` → `性能` → `性能报表` → 计数器报表 → 勾小区级 KPI → 导出 CSV；告警：`维护` → `告警` → `历史告警` → 导出。或北向 FTP `/ftp/pm/` 直接捞计数器文件。
- **中兴 NetNumen U31**：`性能管理` → `报表管理` → `历史性能报表` → 对象类型=小区 → 导出 CSV；告警：`告警管理` → `告警查询` → 导出。
- **爱立信 ENM / OSS-RC**：`ENM` → `Batch PM` → 建导出任务（CSV/XML）→ 小区级 counter；告警：`Alarm and Event` → Export。
- **诺基亚 NetAct**：`Operations` → `Performance Management` → `Report Manager` → 小区 KPI 报表导出；告警：`Fault Management` → `Alarm List` → 导出。

> 没细粒度权限时，直接找**网优工程师 / O&M 值班**，说"要一份某地市/某基站的小区级 KPI 历史报表（CSV）+ 同期告警导出"，他们通常几分钟就能导出。

## 五、最小样例（你们的导出大概长这样）

表头（华为风格，仅供参考，列名不同照常可用）：

```csv
Time,eNodeB ID,LTE_RSRP,LTE_RSRQ,SINR,CQI,DL_Throughput,UL_Throughput,Packet_Loss
2026-09-25 08:15:00,BTS-101,-118,-19,-5,3,4.2,0.8,6.1
2026-09-25 08:30:00,BTS-101,-90,-10,12,13,62.0,11.0,0.2
```

> 只要包含「时间 + 小区标识 + 任意一类 KPI」，上面两行就足够我们验证整条管线。

## 六、拿到文件后怎么用（回流说明，给对接的同事看）

把 CSV 发回给我们后，我们会：
1. 在配置里填 `dataset_path`（文件路径）+ `column_aliases`（列名映射，列名不一致时填）；
2. 跑离线自检脚本确认解析正确；
3. 接运维 Agent 做根因分析（真实 5G 根因需配合 LLM）。

无需你们改任何代码——纯配置切源。
