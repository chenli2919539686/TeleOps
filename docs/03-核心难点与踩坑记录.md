# TeleOps 核心难点与踩坑记录

> 版本：v0.8.22 · 整理时间：2026-09-06
> 本文是「为什么这么设计」的沉淀，按版本/主题归类。技术栈与搭建流程见 `01/02`。
> 命令行操作细节见 `docs/安全加固使用指南.md`。

---

## 0. 总览：四类反复踩的坑

1. **多租户隔离**——读过滤不等于写过滤，缺一层就「所有人的 Agent 在一起变」。
2. **进程管理**——Windows 下「PID 存活 ≠ 服务健康」，uvicorn 派生子进程、PID 文件会说谎。
3. **可观测/可信**——旁路能力（审计、限流）绝不能拖垮主流程。
4. **可维护性**——测试污染生产状态、依赖版本漂移，都是隐性炸弹。

---

## 1. 多租户三层隔离（v0.8.9 → v0.8.18）

### 1.1 难点：读过滤 ≠ 写过滤
v0.8.9 只做了「读过滤」（公共域 + 本人私有域），**写接口完全没有归属校验**。前端默认停在列表第一个域（正好是公共域 `core-net`），结果所有人往同一个域里增删改 Agent，表现为「多用户共用一套 Agent」。

**解法**：统一入口 `workspace_store.is_visible_to()` / `is_writable_by()`，所有 `POST|PUT|DELETE /workspaces/{ws_id}/...` 先校验；越权写 → 403，越权读 → **404**（不暴露域是否存在）。

### 1.2 权限矩阵（v0.8.15 起）

| 操作 | 公共域 `core-net` | 自己私有域 | 别人私有域 |
|---|---|---|---|
| 查看 | ✅ 所有人 | ✅ 本人 | ❌ 404 |
| 增/改/删 Agent | 🔒 仅 admin | ✅ 本人 | ❌ 403 |
| 改自动/手动模式 | 🔒 仅 admin | ✅ 本人 | ❌ 403 |
| 删业务域 | 🔒 仅 admin（默认域受保护） | ✅ 本人 | ❌ 403 |

### 1.3 告警流多租户（v0.8.18）
「实时告警流」曾是**全局单例**——任何机器点启动，所有人（含 admin）都看到同一条流在跑，且「停止」只有启动者本机解锁，管理员看着 LIVE 却停不掉。

**解法**：单例改 `_streams` 字典（每业务域一条独立流水线）；启停沿用 `is_writable_by()`；`status` 返回 `started_by`，前端显示「由 xxx 启动」；停止按钮随**真实运行状态**联动（本域在跑任何人可停）；切域/切身份重置增量水位防串台。

### 1.4 匿名也隔离（v0.8.13+）
`owner_id=-1` 的匿名用户**仅可见公共域**，不暴露任何人的个人域；`owner_id=None` 保留为系统/管理视角（返回全部），仅后台/测试用。

### 1.5 测试踩坑
`tests/conftest.py` 的 `auth_headers` **不保证是 admin**（多个测试文件共用 session 级 DB，「第一个注册用户=admin」不成立）。需要管理员身份的用例必须用 `admin_headers`（显式 `create_user(is_admin=True)`）。

## 2. 进程管理（v0.8.22，最难的一类）

### 2.1 难点：uvicorn 派生子进程，PID 文件说谎
`python -m uvicorn` 启动时，Popen 拿到的是**启动器存根**（~6MB），真正监听 8000 的是它**派生的子进程**（~96MB）。
- 只杀 PID 文件记的进程 → 留孤儿继续占端口 → 表现为「stop 后服务还活着」。
- 改了 DB 但 registry 是内存态，没重启 → 残留旧 Agent/域。

**解法**（teleops_ctl.py）：
- `_kill_pid` 用 `taskkill /F /T /PID` 杀**进程树**；
- `start` 等端口就绪后，用 `find_pid_by_port(8000)`（netstat 反查）**回写真实监听者 PID** 到 `.server.pid`；
- `status` 同时展示「PID 文件值」与「端口实际持有者」，不一致即告警；
- PID 存活但未监听端口的失效记录 → 忽略并继续启动，不误报「已在运行」。

### 2.2 铁律
> **Windows 下 PID 存活 ≠ 服务健康，一切以端口监听为准**（netstat 反查）；PID 文件只是缓存，start 成功后回写真实监听者 PID。

### 2.3 Caddy PID 自愈（v0.8.22）
`caddy_runner.py` 的 `caddy_status()` 以 **443 监听**为准；PID 文件丢失/过期但端口由 caddy 持有时，**反查真实 PID 并回写 PID 文件自愈**，避免误报未运行、`caddy off` 停不掉。`caddy_stop()` 端口兜底杀进程，**且 `_pid_is_caddy()` 校验通过才杀**——防误杀占用 443 的其它服务。

### 2.4 测试污染生产文件（真实缺陷，v0.8.21→0.8.22）
`tests/test_caddy_runner.py` 的 `test_pid_handling_when_no_pid_file` **直接 `unlink` 生产 `data/.caddy.pid`** → 测试跑完，Caddy 实际在跑但 status 误报「未运行」，正是用户某次「重新打开网页服务失败」的元凶之一。

**解法**：所有触碰 `data/` 运行时文件的用例一律 `monkeypatch + tmp_path`，绝不碰生产文件。

## 3. 可观测 / 可信（旁路能力不拖垮主流程）

### 3.1 多租户操作审计（v0.8.21）
多人共用平台，「谁在何时动了什么」必须可回溯。新增 `audit_log` 表 + 14 个埋点 + `GET /audit` + 前端「🧾 操作审计」视图。

**关键设计取舍**：
- **写入永不阻断主流程**：`db.audit()` 内部 `try/except` 静默吞异常，审计表出问题也不会让业务 500——审计是旁路，不能成为可用性依赖。
- **越权被拒也留痕**（`result=denied`）：审计相对「只记成功」的核心价值在于事后追责。
- **与读写隔离共用 `is_visible_to()`**：新增租户维度接口时，审计查询隔离规则自动与业务一致，不出现两套口径漂移。
- 匿名 401；普通用户 `scope=own`；admin `scope=all`；指定他人私有域 → 404。

### 3.2 频率限制（v0.8.12）
自研零依赖滑动窗口（不引 slowapi）：登录 5 / 写 60 / 读 120 每分钟每 IP；`/health /metrics /static` 不计额度；超限 429 + `Retry-After`。阈值用 `TELEOPS_RATE_LIMIT_{READ,WRITE,LOGIN}` 覆盖，设 `off` 全关。

### 3.3 邀请码（v0.8.10）
`TELEOPS_INVITE_CODE` 非空 → 注册必填；错/空统一 403，防旁路探测。`/auth/status` 暴露 `invite_required`。

### 3.4 共享机器登出黑名单（v0.8.14）
多人轮流用同一台机器，前一人 admin 直接关浏览器（没登出），JWT 残留 `localStorage` → 下一人看着像游客、实际渲染 admin 界面。

**解法**：`POST /auth/logout` 把当前 JWT 加服务端黑名单（持久化 `data/jwt_revoked.json`，重启仍失效）；每个 JWT 带唯一 `jti`，仅被自己登出的那一个失效；前端启动即校验身份并渲染「当前账号」chip，消除窗口期。

## 4. 依赖与版本漂移

### 4.1 LangGraph 版本锁（致命）
`langgraph>=0.2,<0.3`（当前 0.2.76）。1.x 重构了 `langgraph.graph` 的导出与 `StateGraph` 语义，装到 1.x 会直接 `import` 失败。**requirements.txt 已用上限锁死，升级前必须评估 API 兼容性**。

### 4.2 ChromaDB / 字符级兜底
`kb_store.py` 优先 Chroma，无则字符级重叠打分——**专门解决中文无空格分词**在向量库缺失时的检索降级，保证任意机器都能跑 RAG。

### 4.3 requests 漏声明（v0.8.21 部署打磨）
`real_adapters.py`（Zabbix/ELK 网络调用）用到 `requests`，但 `requirements.txt` 漏声明，导致干净部署 `import` 失败。已补 `requests>=2.28`（根 + deploy 两份 requirements 同步）。

## 5. 前端缓存陷阱

每次前端大改后，`web/index.html` 必须更新 `app.js?v=x.x.x` 缓存戳，浏览器需 `Ctrl+Shift+R` 强刷，否则加载旧 `app.js`，表现像「改了没生效」。多租户/审计等版本均在缓存戳里留痕（如 `?v=0.8.21`）。

---

## 6. 其它维护经验

- **DB 改完必须重启后端**：registry 是内存态，`_sync_registry()` 启动从 DB 全量重建，个人域 Agent 重启不丢。
- **E2E 脚本清理**：`scripts/test_real_llm_e2e.py` 跑完清理注册的测试用户与孤儿域（owner 已删的 workspace），否则页面残留账号。
- **Caddy 二进制下载**：沙箱到 GitHub release 持续 `ConnectionResetError`，`caddy_setup.py` 提供本地 zip 模式 + winget 备用；用户可从浏览器手动下 `caddy_2.11.4_windows_amd64.zip` 后传路径。
- **Docker 上下文**：compose 文件在 `deploy/`，`context` 需指向项目根，才能正确解析 Dockerfile 中的 `deploy/requirements.txt`。
