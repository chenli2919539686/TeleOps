# TeleOps 方法论验收文档（Methodology & Acceptance）

> 用途：面向「电信运营商运维 / 研发岗」求职作品验收与面试讲述。本文把项目从**工程治理**角度收敛成一份可照着讲的材料——不堆功能列表，而讲「为什么这么决策、谁负责、有什么风险、数据怎么落地、怎么保证质量、怎么验收」。
> 关联文档：`docs/04` 能力对照与优化路线 · `docs/06` 多副本部署实战验证 · `docs/10` 百人规模生产部署清单 · `docs/11` 合规与数据主权方案 · `docs/12` 一键演示与走查。
> 版本基线：v0.8.49（HEAD `fad0919`）。

---

## 0. 一句话定位

TeleOps 是一个**面向百人规模电信内部团队**的「运维告警 RCA 作战室」Agent 平台：告警进来 → 运维 Agent 给根因假设 → 发现缺工具 → 研发 Agent 现场造工具并复用 → 全程审计可回放 → 高危动作走人工审批（HITL）。它是**单进程即可演示、切配置即可上生产**的渐进式架构，不是玩具 Demo，也不是为炫技而过度设计的分布式系统。

## 1. ADR 架构决策记录（Architecture Decision Records）

> 原则：每个关键决策都记录「背景 / 决策 / 后果 / 备选」，方便评审人快速判断设计成熟度。

### ADR-001 技术栈：FastAPI + LangGraph + 原生 JS 前端 + 单进程
- **背景**：求职作品需在一个月内可演示，且要让面试官看清全链路，而非被脚手架淹没。
- **决策**：后端 FastAPI（异步、易测）；Agent 编排用 LangGraph（状态图可控、可暂停/恢复，契合 HITL）；前端用原生 JS + 静态文件（零构建，启动即见）；单进程 uvicorn 起服务。
- **后果**：✅ 零构建心智负担、改动即时可见、测试入口简单；⚠️ 单进程需靠「状态外部化开关」才能横向扩展（见 ADR-003）。
- **备选**：React+Vite（更现代但引入构建链与状态管理复杂度）；Django（重、异步弱）。

### ADR-002 多租户：A 档（单机单进程 + 注册建个人域 + 接口过滤）
- **背景**：百人团队需要租户隔离，但 K8s 命名空间级隔离对求职作品是过度工程。
- **决策**：注册自动建个人域 `ws-<用户名>` 并复制默认 4 个 Agent；`/workspaces`、`/agents` 按 `owner_id` 过滤；公共域 `core-net`（`owner_id=NULL`）所有人可见；**写隔离**经 `is_writable_by()` / `is_visible_to()` 服务端唯一判定入口。
- **后果**：✅ 零额外运维、隔离逻辑集中可测；⚠️ 单机承载，需水平扩展时配合 ADR-003。
- **备选**：B 档（每租户独立库）——隔离更彻底但运维与演示成本陡增，求职阶段不划算。

### ADR-003 状态外部化：统一开关 `TELEOPS_STATE_STORE=local|redis`
- **背景**：多副本下「A 副本发起的任务、B 副本看不到」会导致前端状态灯永远转圈。
- **决策**：把四类进程内状态（限流窗口 / 异步任务 / 告警流状态 / 并发信号量）抽象为 `Store` 接口，默认 `local`（零行为变更），设 `redis` 即外移；四类共用同一开关，避免配置分裂。
- **后果**：✅ 默认零变更、一键切 Redis 即「副本无状态」；⚠️ 播放面（RQ worker）需 Redis≥4.0 + Unix `fork()`，Windows 起不来（见 ADR-004）。
- **备选**：Celery 全量接管——功能强但依赖重、与现有线程执行器割裂。

### ADR-004 告警流执行器：默认线程、队列给 Linux
- **背景**：告警流是长生命周期线程，无法直接放进 Redis；且 Windows 无 `os.fork`。
- **决策**：`TELEOPS_STREAM_EXECUTOR=thread|queue`。默认 `thread`（demo 零变化）；`queue` 走 RQ，给 Linux/WSL2 部署。剧本不进 Redis（确定性 seed=42 重建），共享状态只放「播到第几条」。
- **后果**：✅ demo 与生产线一致；⚠️ Windows 只能验证状态/控制面跨副本，逐条播放需 Linux worker。

### ADR-005 HITL 两层闸 + 审批态外部化
- **背景**：企业级护城河是「高风险动作可控」，但闸写错位置会变死代码（曾写在 `server.agent_build` 死代码里）。
- **决策**：① 构建期全局闸（`TELEOPS_REQUIRE_APPROVAL` 或 admin 运行时开关）作用于 `tool.build` + `stream.start`；② 运行时按工具风险二次确认（`ToolRegistry.require_human_approval` 列表，如 `restart_service`）。审批单与运行时设置经 `TELEOPS_STATE_STORE=redis` 跨副本共享（fail-closed）。
- **后果**：✅ 开关真生效、多副本审批态一致；⚠️ 审批态默认落本地 JSON，多副本投产才需接 Redis。

### ADR-006 合规红线：未做「数据不出域 + 模型私有化」前不接真实告警/拓扑/日志
- **背景**：默认 LLM 是 DeepSeek 公有云，真实告警/拓扑送出去即违规。
- **决策**：硬红线——真实数据源接入前置条件 = 数据不出域（私有网络）+ 模型私有化（`TELEOPS_LLM_BASE_URL` 指向本地 OpenAI 兼容推理，**零代码改动**）。
- **后果**：✅ 默认演示只用合成 5G 样本，合规零风险；⚠️ 真实数据闭环被「拿不到私有化环境」阻塞（见风险 R1）。

### ADR-007 配置驱动 + mock 兜底（零依赖可演示）
- **背景**：面试官机器多半无 DeepSeek Key、无 Prometheus、无 OSS 桶。
- **决策**：LLM / 监控适配器（Prometheus/Loki）/ OSS / OIDC 全部「配置驱动 + 未配置自动回退 mock/demo」，保证任何环境一条命令跑通。
- **后果**：✅ 演示确定性极高；⚠️ 需在每个适配层维护 mock 与真实两条路径。

### ADR-008 数据源抽象：5G 数据集 loader 方向感知 + 列别名映射零代码切源
- **背景**：真实 OSS（华为/中兴/爱立信）列名千差万别，loader 写死列名就无法复用。
- **决策**：`FiveGKpiAdapter` 内置 `_COLUMN_ALIASES` + 配置 `column_aliases` 覆盖；`iter_rows`/`load_payloads` 透传别名；指标按方向（RSRP/RSRQ 越低越差）分别定阈值，payload 自带 severity。
- **后果**：✅ 任意厂商 OSS 填 `dataset_path`+`column_aliases` 即切源，零代码；⚠️ 仍卡真实导出文件（R1）。

### ADR-009 DB 方言翻译层：SQLite 默认 / Postgres 可切
- **背景**：演示要轻，生产要稳。
- **决策**：`TELEOPS_DB_DSN=postgresql://...` 即切，默认仍 SQLite；`db.py` 加 `_translate_sqlite_to_pg`（AUTOINCREMENT→IDENTITY、占位符 ?→%s、executescript 拆句）。
- **后果**：✅ 一套代码双后端；⚠️ PG 需额外驱动与迁移纪律。

### ADR-010 RBAC 引擎接线：路由层 `assert_perm` 正交叠加租户闸
- **背景**：RBAC 引擎 `enforce` 早已写好却是死代码（路由层零调用）。
- **决策**：`src/api/deps.py::assert_perm` 为路由层唯一权限判定入口，在租户闸之上叠加能力闸（`stream_start`→`tool.exec`、`build_agent`→`agent.manage`）；`/admin/roles` 可运营角色（`org.manage` 闸 + 两道锁死闸）。
- **后果**：✅ 越权写→403、越权读→404；✅ 不放松既有 admin-only 闸。

## 2. RACI 责任分配矩阵

角色（来自 `src/core/db.py` `BUILTIN_ROLES`）：`super_admin`(全权) / `org_admin` / `sre` / `dev` / `viewer`；新注册用户默认角色 `sre`。外加「平台/系统」列表示基础设施责任方。

| 活动 | super_admin | org_admin | sre | dev | viewer | 平台/系统 |
|---|---|---|---|---|---|---|
| 账号注册 / 登录（自服务） | A | I | I | R | R | R(执行) |
| 邀请码开关（`TELEOPS_INVITE_CODE`） | A/R | R | I | I | I | — |
| 组织节点 / 成员 / 角色管理（`org.manage`） | A | R | I | I | I | — |
| 业务域 CRUD（`ws.manage`，公共域仅 admin 可写） | A | R | C | I | I | — |
| 域内 Agent 增删改（`agent.manage`） | A | C | R | R | I | — |
| 告警确认 / 启动告警流（`alert.ack`） | A | C | R | I | I | — |
| 工具执行 / 造工具（`tool.exec`） | A | C | R | I | I | — |
| 高危动作人工审批（HITL） | A/R | R | C(提请) | C(提请) | I | — |
| 审计查看（`audit.view`） | A | R | R | I | R | — |
| 审批单批准 / 拒绝 | A/R | R | I | I | I | — |
| 部署 / 扩容 / Redis / Caddy | A | C | C | I | I | R(执行) |
| 合规与数据主权决策（红线） | A | C | I | I | I | C |

图例：R=负责执行 · A=批准/问责 · C=被咨询 · I=知会。

## 5. 三环境策略（Dev / Staging / Prod）

> 核心约束：**数据不出域、模型可私有化**是真实环境的前置条件（ADR-006）。

| 维度 | Dev（本地/演示） | Staging（预发/验收） | Prod（生产） |
|---|---|---|---|
| 数据库 | SQLite（默认） | Postgres（`TELEOPS_DB_DSN`） | Postgres（主从） |
| 副本 | 单进程 | 多 worker（`--workers N`）+ Caddy 多后端 | 多副本 + Redis 状态外置 |
| 状态层 | local | redis（可选） | redis（`TELEOPS_STATE_STORE=redis`） |
| LLM | mock / DeepSeek | 模型私有化端点 | 模型私有化（不出域） |
| 数据 | 合成 5G 样本 | 脱敏/合成 | 真实 OSS（须满足红线） |
| 接入 | 本机 8001 前端 | Caddy HTTPS + 防火墙白名单 | Caddy HTTPS + OIDC + 邀请码 |
| 合规 | 不出域（无真实数据） | 等保二级测评 | 等保三级测评（docs/11） |
| 用途 | 开发/面试演示 | 验收/压测 | 百人团队日常 |

**环境晋升规则**：Dev 验证 → Staging 跑全量 pytest + 量化基准（Top-1/噪声抑制/修复率）→ Prod 仅在生产就绪清单（docs/10 §上线检查清单）全绿后放开真实数据源。

## 6. 质量门（Quality Gates）

### 6.1 当前测试资产（已落地）
- **规模**：测试套件共 **282 个测试函数**（pytest 节点约 **410**，含参数化）；本地入口 `pytest tests/ -q`。
- **依赖外部件的用例**：约 6–12 个依赖 Redis / Postgres 的用例（如 `test_multi_replica_redis`、`test_approvals_redis_externalized`、`test_db_postgres` 真连分支）在本机未起对应服务时自动 `skip`，不阻断。
- **覆盖范围**：RBAC 接线、状态外部化（限流/任务/流/信号量）、HITL 审批、审计时间线、适配器（5G/OSS/Prometheus/Loki）、根因基准、OIDC、多租户隔离、Caddy 渲染等核心闭环均有专属测试文件。

### 6.2 合并门槛（零回归是硬指标）
- 任何改动不得引入**新的**失败；全量 `pytest tests/ -q` 须 `exit 0`。
- 语法/类型门：`python -m py_compile src/**/*.py` 全绿；前端 `node --check web/app.js` 全绿。
- 已知豁免（非产品缺陷，属测试隔离 flake）：`test_audit_export::test_export_admin_sees_all_but_user_isolated` 与 `test_oss_export::test_archive_json_format` 在共享 session-DB 全量跑时偶发 `sqlite3.OperationalError`，**隔离运行（`-k` 指定）均绿**；修复方向是这两个导出测试改用独立 DB fixture（待办，见 §7）。

### 6.3 CI 待办（当前缺口，诚实标注）
- **现状**：仓库 `.github/` 尚不存在，**真实 GitHub Actions CI 未接线**（EVOLUTION_BACKLOG 已知待办）。当前质量靠本地 + 手动全量跑保障。
- **目标门禁**（落地后）：lint(`ruff`) → 类型(`mypy` 可选) → 单测(`pytest`，Redis/PG 用 service 容器) → 密钥扫描(`gitleaks`) → 构建(`py_compile` + 前端 `node --check`) → 部署清单校验。失败即阻断合并。

## 7. 验收清单（面试照讲 / 上线核对）

- [x] 多租户硬隔离：注册建个人域 + 读/写双层闸（越权写→403、读→404）

## 8. 给面试官的三句话

1. **这不是 Demo，是可演进的系统**：单进程能演示，切 `TELEOPS_STATE_STORE=redis` 就变多副本无状态，切 `TELEOPS_DB_DSN` 就上 Postgres——架构决策都有 ADR 背书。
2. **安全与合规是设计约束，不是补丁**：多租户读写双闸、RBAC、`HITL`、数据不出域红线，全部在第一次写代码时就作为硬约束落地。
3. **诚实面对边界**：MTTR 用占位不编造、CI 还没接、真实数据卡合规——我把「已知缺口」写进风险登记册和验收清单，而不是假装完成。
